连接与管理 agents

AgentsDock 支持在你连接的服务器上使用 Claude Code、Codex、OpenCode 和 Cursor。连接 provider 有两种方式：在服务器上使用 provider 自己的 CLI 登录，或者为这个 provider 配置自定义 API endpoint。

支持的 provider

Claude Code Codex OpenCode Cursor

两种连接方式

  • CLI Login 使用安装在远程服务器上的 provider CLI 或 runtime。
  • Custom API 使用你为当前服务器配置的 endpoint 和 token/key。

CLI 登录

请在运行 AgentsServer 的那台机器上执行登录命令。provider 完成登录后，回到 AgentsDock 重新检查对应 provider。

# Claude Code
claude auth login

# Codex
codex login

# OpenCode
opencode auth login

# Cursor
cursor-agent login
  • Claude Code 会在下一次发送消息时确认登录；重新检查只验证 CLI 是否安装。
  • Codex 使用保存在这台服务器上的 Codex CLI 登录。
  • OpenCode 使用 opencode auth login 登录你在 OpenCode 里选择的模型 provider。
  • Cursor 的命令可能是 cursor-agent 或 agent，以你服务器上安装的命令名为准。

如果某个 provider 仍显示 Not connected，先确认你正在看正确的服务器，然后在对应卡片里点 Recheck。

Custom API

如果你想让 AgentsDock 使用 endpoint，而不是 provider 默认的 CLI 登录，可以使用 Custom API。自定义 endpoint 通常需要 API base URL 和 API key 或 token。有些 provider 还会在高级选项里提供 protocol、model、auth header 等字段。

  • Claude Code 的 Custom API 使用 Anthropic-compatible endpoint。
  • Codex 在它自己的 provider 卡片里提供对应的 API 配置。
  • OpenCode 的 Custom API 支持 Anthropic、Chat Completions 和 Responses-compatible endpoint。
  • Cursor 的 Custom API 使用 Cursor API endpoint 和 Cursor API key。

Custom API 设置保存在当前服务器上。如果你有多台服务器，需要在每台想使用它的服务器上分别配置。

在会话中使用

provider 连接好以后，新建会话，在左下角的 provider picker 里选择它。AgentsDock 会显示当前服务器上所有已经可用的 provider，所以切换服务器后列表可能会变化。如果同一个 provider 同时有 CLI 登录和自定义 endpoint，自定义 endpoint 会作为一个独立选项显示，不会和 CLI 登录混在一起。

管理 agent 状态

打开 Settings → My Agents 可以查看当前服务器上哪些 provider 已连接。这个页面按服务器分别配置：如果你切换到另一台服务器，可用的 provider 也可能不同。

如果还没完成基础配置，先看 客户端安装，再按 搭建指南 连接服务器，然后继续 开始第一个会话。
